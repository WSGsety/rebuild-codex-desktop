# 正式产物改为 7z（2026-11-07）

正式 Windows 全量包使用 `7zz a -t7z -m0=lzma2 -mx=5 -ms=on`：LZMA2 标准档、固实压缩，保留全部文件。生成后执行 `7zz t`，通过后再写入本地构建复用记录；Actions 继续生成 SHA256 并验证发布附件。

## 同一发布包的实测

输入为当前已发布的 `Codex-win-x64-26.1029.70936-cli-0.167.0.zip`，1,007,388,410 字节，下载后核对了 Release 提供的 SHA256。没有使用不同版本内容来比较格式。

在同一台 Mac arm64、7-Zip 26.05 上，使用相同解压目录顺序测试：

| 格式 | 体积（MiB） | 压缩耗时 | 解压耗时 |
| --- | ---: | ---: | ---: |
| 原 ZIP 标准档，同机重打包 | 960.72 | 56.44 秒 | 未计时 |
| 7z 快速档 `-mx=3` | 792.74 | 29.09 秒 | 2.97 秒 |
| **采用：7z 标准档 `-mx=5`** | **676.58** | **118.96 秒** | **3.52 秒** |

7z 标准档相对当前发布 ZIP 减少 284.14 MiB（约 29.58%），本地压缩多约 63 秒。用户优先考虑不稳定网络下的下载体积，因此采用标准档；这些是单机样本，不直接代表 Windows Actions 耗时，也不保证以后所有版本都有相同压缩率。

两份 7z 均重新解压，3,691 个文件逐一比较 SHA256，另检查 566 个目录，全部与原发布 ZIP 一致。没有裁剪 WSL/Linux 程序或其他资源。ZIP 同机重打包的条目、原始大小和 CRC 也与发布包一致。详见[原始数据](sevenzip-comparison.json)。

## 发布迁移

- 新产物名：`Codex-win-x64-<App版本>-cli-<CLI版本>.7z`，标签仍为 `v<App版本>-cli-<CLI版本>`。
- 定时/手动跳过判定必须同时匹配版本标记、对应标签的 7z 和 `SHA256SUMS.txt`。只有旧 ZIP 或缺少校验文件时继续构建，避免同版本无法迁移。
- 历史 ZIP 附件不自动删除。若在同一标签补发 7z，当前校验文件与发布说明改为对应 7z，旧 ZIP 可能仍保留在附件列表中。
- 使用 7-Zip 或支持 7z 的工具完整解压到新目录，启动方式不变。需要固定 `.zip` 下载地址的外部脚本应改用 `.7z`。
- 本地成品复用指纹包含构建脚本，格式变化后不会错误复用旧 ZIP。CI 每次完整构建并测试归档。

本地测试验证的是格式、目录和内容完整性，未在 Windows 上实际启动这个重压缩测试包。正式构建的 Windows CLI 冒烟检查和全部既有测试仍保留，执行结果以 PR 的 Actions 检查为准。
