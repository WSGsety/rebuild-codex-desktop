# ZIP 体积与速度取舍（2026-11-07）

本次 ZIP 调参的结论：恢复原 `7zz a -tzip -mx=5`，不采用额外压缩参数调整。随后另行完成了 [7z 同版本实测](sevenzip-comparison.md)，当前正式发布方式已选择 7z。下面保留试验数据，避免把相对试验快速档的收益误当成相对当前发布流程的收益。

在同一新版内容上，候选参数相对原标准档只减少 3.21 MB，即 3.06 MiB、约 0.32%，本地压缩增加约 18 秒，收益不足以采用。当前公开发布包 App `26.1029.70936` 为 1,007,388,410 字节（960.72 MiB），而试验使用新版 App `26.1103.31037`；不同版本不能直接比较压缩效果。

CI 的依赖精简、缓存收敛、文档跳过、PR 取消及本地重复构建复用仍保留。此 ZIP 调参阶段未变更发布格式，也未删减程序文件。

## 实包对比

同一目录、同一台 Mac arm64 主机、7-Zip 26.05，MSIX `26.1103.3517.0` / App `26.1103.31037` / CLI `0.167.0`。下列体积使用十进制 MB（1 MB = 1,000,000 字节），耗时只含压缩，不含下载、解包、补丁及 CLI 替换。

| 参数 | ZIP 大小 | 本地压缩时间 | 结论 |
| --- | ---: | ---: | --- |
| 原快速档 `-mx=1` | 1,065.22 MB | 17.06 秒 | 快，但下载体积较大 |
| 标准档 `-mx=5` | 1,015.19 MB | 70.56 秒 | 主要体积收益已获得 |
| 高压缩档 `-mx=7` | 1,007.94 MB | 约 222.36 秒 | 比标准档仅少 7.25 MB，耗时明显增加 |
| 试验平衡档（未采用） `-mx=5 -mfb=128` | 1,011.98 MB | 88.37 秒 | 比标准档再少 3.21 MB，增加约 18 秒 |
| 最高档 `-mx=9` | 未完成，不计入比较 | 运行至少 267.3 秒后主动停止 | 不以未完成 ZIP 的体积判断压缩率 |

平衡档测试显式传了 `-mpass=1`；试验候选命令省略这一默认值。7-Zip [编码器实现的 Normalize](https://github.com/ip7z/7zip/blob/main/CPP/7zip/Compress/DeflateEncoder.cpp) 显示，标准档默认一次优化、快速匹配长度 32；高档和最高档会分别增加为 3 和 10 次优化，匹配长度也增加。将标准档的匹配长度提高至 128，可以避免高档的多轮耗时。

高压缩档时间由 ZIP 文件创建至最终写入时间计算，属于近似压缩写入耗时；其他完成档位为实际进程墙钟时间。单次测量会受系统负载影响，不能直接替代 GitHub Windows runner 的时间。最高档未完成，因此不宣称这组参数在所有可能参数中达到数学上的最小 ZIP。

[原始测量数据](zip-compression.json) 保留确切字节数与未完成项。

## 完整性和兼容性

- 完成的四种压缩包均为相同的 4,284 个条目，文件名、原始大小、CRC 完全一致；ZIP 条目只使用 Store/Deflate。
- 对试验平衡档逐文件解压并与原目录比较 SHA256，验证全部 3,717 个普通文件内容一致，其余条目为目录。
- 保留全部 Windows / Linux 可执行文件及资源，不因扩展名或疑似重复而裁剪。没有改变 ZIP 文件命名、校验和、启动方式及下载接口。
- 19 项脚本回归通过；完整 Windows 构建及 CLI 冒烟检查由当前 PR 执行，其状态以 PR 检查结果为准。

最终未增加原发布流程的压缩力度。包仍约 1 GB，单纯调整 ZIP 压缩参数不能消除网络中断风险。
